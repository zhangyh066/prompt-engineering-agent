# 产品短板与演进方向

## 核心判断

PEA 当前已经是一个可运行的工作流产品，但还不是稳定的“智能 Prompt 专家”。最强的部分是状态、接口、历史和实验控制；最弱的是语义判断、偏好学习和跨任务经验积累。

## 主要短板

### 1. 规则编排强，语义生成弱

意图分类和策略选择仍主要依赖关键词与模板。它能识别常见任务，却难以理解讽刺、隐含受众、复杂业务关系和跨段落冲突。继续增加规则只会得到更庞大、更脆弱的编译器。

**方向**：保留现有确定性基线作为可解释后备，同时增加模型驱动的结构化语义规划器；所有模型建议仍进入相同 Pydantic 契约。

### 2. “写得更长”与“写得更有用”没有分离

字数、F1、格式合格率和人工可用性可能互相冲突。邮件案例已经证明，行动请求和简洁表达可能挤掉真正重要的补救细节。

**方向**：把详略程度作为一等用户偏好，并默认优先保留事实、约束和具体行动信息。

### 3. 缺少真正的反事实能力

系统通常生成一个主方案，很少主动回答：“如果最初假设错了呢？”、“什么时候另一个方案更好？”、“什么证据会推翻当前结论？”

**方向**：探索模式下生成替代假设、反证和方案切换条件，而不是只增加 Self-critique 标题。

### 4. 每次运行都从零开始

历史数据库目前只保存结果，没有把“哪类任务、哪种策略、什么原因导致收益或退化”转化为下一次可复用经验。

**方向**：建立带证据的策略记忆，按任务和模型检索成功案例；新任务先参考经验，再通过当前评估验证，不能盲目套用。

### 5. 评测容易优化错目标

分类准确率、Token F1、人工偏好、成本和延迟不是同一目标。单一总分容易隐藏某一类别严重退化，Mock 和 LLM 子 Agent 也不能替代生产 API。

**方向**：分任务主指标、成本—质量 Pareto、人工盲评校准，以及对失败案例的因果归因。

### 6. 测试集已经被多轮开发使用

旧 80 条、dev 和最终模拟 test 都不同程度参与了开发。继续在同一批数据上优化会逐步把 Benchmark 变成训练答案。

**方向**：正式发布前建立新的私有或近期 holdout，锁定当前数据为开发资产。

### 7. 缺少可协作的中间表示

用户目前只能接受整段生成结果，不能锁定一段、删除一段、只重写验收标准，或将某个约束标记为不可更改。

**方向**：将 Prompt 表示为可编辑 Blueprint，每个模块都有来源、理由和版本；前端支持局部编辑与局部重生成。

### 8. 产品界面与生产运行仍有差距

Streamlit 适合本地产品，但当前仍是同步、单实例、无多用户权限模型。真正团队协作需要任务队列、持久化中断、审计权限和共享工作区。

**方向**：本阶段先把本地产品体验做完整，不把“能启动网页”包装成多租户 SaaS。

## 实施优先级

1. 详略偏好与探索式替代方案。
2. 可编辑 Blueprint 与模型增强语义规划。
3. 策略记忆和失败归因。
4. 新 holdout、真实模型对照和人工校准。
5. 团队协作与持久化运行基础设施。

这些方向强调生成质量、可解释性和产品价值，不以增加防御性分支数量作为主要进展。
