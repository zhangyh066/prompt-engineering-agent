# PEA 产品需求文档（PRD）

## 1. 产品定位

PEA（Prompt Engineering Agent）是一个本地优先的 Prompt 诊断、生成、执行评估和版本管理工作台。它面向需要反复改进提示词的内容创作者、办公人员、运营团队和 AI 应用开发者。

产品价值不是“把 Prompt 写得更长”，而是帮助用户保留意图、发现缺陷、选择合适策略，并用证据判断修改是否有效。

## 2. 目标用户与任务

### 内容创作者与办公人员

- 将模糊需求整理成可直接执行的写作、邮件、总结或研究 Prompt。
- 控制详略、风格和探索程度。
- 保存可复用版本并导出结果。

### AI 应用开发者与评测人员

- 使用统一 Gateway 对接 OpenAI-compatible 与 Anthropic。
- 对原始、通用和自适应 Prompt 做对照实验。
- 查看 Token、成本、延迟、稳定性和失败记录。
- 通过 Promptfoo 或 API 将评测接入外部流程。

## 3. 核心用户流程

```text
输入需求或原始 Prompt
→ 意图与完整性分析
→ 必要时澄清
→ 八维诊断
→ 策略与详略/探索偏好
→ Prompt 生成
→ 静态或动态评估
→ 有界修订与最佳版本
→ 目标模型适配
→ 历史、比较与导出
```

## 4. 功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F1 | 自然语言与原始 Prompt 输入 | 非法输入被拒绝；必要信息不足时可中断并恢复 |
| F2 | 意图与诊断 | 输出任务类型、复杂度、约束、八维评分与修改建议 |
| F3 | 动态策略生成 | 按适用条件选择策略，不机械叠加角色或示例 |
| F4 | 用户生成偏好 | 支持详细/均衡/简洁与保守/均衡/探索 |
| F5 | 探索式方案 | 复杂任务可生成替代假设、反证和方案切换条件 |
| F6 | 工作流控制 | 默认最多三次生成，保留最佳版本，支持取消与异常状态 |
| F7 | 静态与动态评估 | 明确区分结构、实际执行和未验证语义指标 |
| F8 | 多模型接入 | 支持 Mock、OpenAI-compatible、Anthropic；不硬编码密钥 |
| F9 | 目标模型适配 | 支持 system/JSON 能力和输出 Token 配置 |
| F10 | 历史与版本 | SQLite 保存运行、逐轮版本、diff、评分与策略变化 |
| F11 | 评测中心 | 展示 100 条 Benchmark 状态和 80 条公共结构审计 |
| F12 | 产品界面 | 提供工作台、历史版本、评测中心、系统状态四个工作区 |
| F13 | 导出与 API | 支持 JSON/Markdown 导出、OpenAPI 和 `/v1/chat/completions` |

## 5. 非功能需求

- **本地优先**：默认 OpenAI；无 API Key 时可显式选择 Mock 运行核心流程。
- **可解释**：每个策略和 Prompt 修改都有理由。
- **可复现**：依赖锁文件、数据哈希、固定抽样种子和结构化报告。
- **成本可见**：记录调用、Token、成本、耗时；真实调用需要显式预算。
- **安全默认**：API 默认绑定本机、不启用 CORS、不展示密钥，具有 Host/请求大小与安全响应头控制。
- **诚实评测**：Mock、子 Agent 和模拟人工不得标记为真实模型或真实人工证据。
- **可维护**：模块化 Python、Pydantic 契约、类型注解和自动化测试。

## 6. 当前版本范围

当前为 0.2.0 Beta，适合本地试用、Prompt 工作流验证和评测工程开发。

已实现 LangGraph 工作流、SQLite、FastAPI、Streamlit、公开数据审计、策略搜索、最终测试访问控制和 Docker 配置。

## 7. 明确不在当前承诺内

- 不保证优化后的 Prompt 在所有模型和任务上更好。
- 不宣称已证明真实正确率提升或优于其他商业产品。
- 不提供多租户认证、权限隔离或公网 SaaS 承诺。
- 不将模拟评审等同于真实人工评审。
- 不承诺 Docker 镜像已在所有环境验证。

## 8. 产品指标

- 优化工作台完成率与澄清恢复成功率。
- 用户对最佳版本的采纳率与局部编辑率。
- 分任务人工偏好、重大失败率和格式合格率。
- 单次优化 Token、成本、延迟与迭代次数。
- 策略在未见数据上的收益和成本—质量 Pareto。
- 评测报告完整率与数据哈希可复现率。

## 9. 主要风险与应对

- **规则语义上限**：引入模型增强规划，保留可解释基线。
- **过拟合公共数据**：使用新 holdout，并公开数据使用历史。
- **评测目标错位**：分任务指标、人工盲评和成本联合判断。
- **本地运行边界**：生产协作另行设计认证、队列和持久化中断。
- **数据许可**：代码与第三方数据分别标注许可证和来源。
